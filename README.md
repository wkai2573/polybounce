# Polybounce

多人合作的彈珠打磚塊遊戲：玩家各佔方形場地的一邊，用擋板接住彈珠，擊碎場地中央的磚塊與怪物。單人可以直接在瀏覽器遊玩，多人用房間碼點對點連線，不需要伺服器。

線上遊玩：https://wkai2573.github.io/polybounce/

## 玩法

- 場地四邊各是一個方位，沒有玩家的方位會變成牆。一個人玩時自己在下方，其餘三邊是牆。
- 玩家用擋板接住彈珠並彈回場地，擊碎磚塊與怪物即過關。
- 彈珠池由全隊共用，每關開始補滿為玩家人數乘以十顆。彈珠池為空且場上沒有彈珠時，全隊失敗。
- 第 3 關起中央會出現怪物，會定期發射子彈，打到擋板使該玩家凍結一秒；子彈不會被磚塊擋住。
- 每 5 關是 BOSS 關。BOSS 輪流施放環形、瞄準扇形與螺旋三種彈幕，血量降到一半以下會狂暴。BOSS 的子彈只凍結 0.5 秒，解凍後有 1 秒無敵。
- 磚塊被擊碎時有機率掉落道具，需要用擋板碰到才能拾取：
  - 多球：場上每顆彈珠各分裂為三顆，最常出現。
  - 補給：彈珠池增加五顆。
  - 加寬：擋板變寬一段時間。
  - 貫通：場上現有的彈珠 6 秒內穿過磚塊與怪物，沿途每次扣 1 血，仍被牆與擋板反彈。
  - 環爆：稀有，場上每顆彈珠原地分裂成 10 顆，向四周散開。
- 房間最多 4 人，開局後不能中途加入。

## 選關與接關

- 單人在主選單、多人由房主在大廳選擇起始關卡（1 到 99），預設第 1 關。
- 失敗後房主可以「從第 N 關接關」（N 是失敗的那一關）：分數歸零、彈珠池補滿、關卡配置換新；也可以「再來一局」回到這一局的起始關卡。其他玩家只能等房主按。
- 最高紀錄只計從第 1 關開始的局；從第 1 關開始後接關的局仍然算同一局，所以接關後打到更高的關卡，紀錄照樣更新。

## 操作

| 操作 | 說明 |
| --- | --- |
| 滑鼠移動 | 沿自己的方位移動擋板，畫面上的準星標示指標位置 |
| 點一下畫面 | 對局中鎖定滑鼠；這一下點擊只用來鎖定，不會瞄準或發射 |
| 左鍵 | 進入瞄準模式，再按一次朝滑鼠方向發射 |
| 右鍵 | 取消瞄準 |
| `Esc` | 解除滑鼠鎖定。房主與單人同時暫停，再點一下畫面就重新鎖定並繼續；其他玩家只是回到「點一下重新鎖定」 |
| `P` | 暫停或繼續，只有房主與單人可用 |
| `M` | 切換靜音 |

瞄準時擋板會被鎖住，且瞄準角度與自己那一邊的表面至少夾 15 度。主選單、大廳、暫停與結算畫面不鎖定滑鼠。瀏覽器不支援或拒絕滑鼠鎖定時，會退回一般的滑鼠行為，此時 `Esc` 直接切換暫停。

## 本機開發

需要 [Bun](https://bun.sh)。

```sh
bun install
bun run dev        # 開發伺服器
bun run build      # 建置到 dist
bun run typecheck  # 型別檢查
bun test           # 執行測試
```

## 版本號

主畫面右下角顯示版本號，格式為 `v主版本.次版本.修訂號`。主版本與次版本寫在 [package.json](package.json) 的 `version`，修訂號是建置時 git 的 commit 總數，所以每次 commit 都會自動遞增，不必手動改。要升主版本或次版本時才修改 package.json。游標移到版本號上可以看到對應的 commit。

## 部署

推送到 `main` 後，[GitHub Actions](.github/workflows/deploy.yml) 會依序跑型別檢查、測試與建置，通過後自動部署到 GitHub Pages。

## 專案結構

```
src/
  core/     遊戲核心，純邏輯，不依賴瀏覽器
  net/      PeerJS 房間與連線，房主權威
  render/   畫面繪製
  audio/    合成音效
  main.ts   輸入、畫面流程與各模組的組裝
docs/
  specs/    產品規格
  adr/      架構決策紀錄
GLOSSARY.md 領域用語表
```

連線採房主權威：房主執行遊戲核心，其他玩家送出輸入並接收狀態，詳見 [ADR-0001](docs/adr/0001-peerjs-host-authoritative.md)。
