# 09：傳輸層與房主權威

**要建置什麼：** 在遊戲核心外側加一個可替換的傳輸介面，實作 ADR-0001 決定的房主權威模型：房主負責全部運算，其他玩家只傳送輸入並接收狀態。這張票先不碰真實的 PeerJS，用假的傳輸讓兩個以上的客戶端在同一個測試行程裡互通。單人模式沿用同一套邏輯，只是沒有任何連線。

**Blocked by（被誰阻擋）：** 01：預先重構

**Status：** ready-for-agent

- [ ] 傳輸介面能讓房主收到各玩家的輸入，並把遊戲狀態送給所有其他玩家
- [ ] 只有房主執行遊戲核心；其他玩家端只送輸入、只顯示收到的狀態
- [ ] 用假的傳輸測試：兩位玩家各自送出輸入，房主端的遊戲依輸入前進，另一端收到一致的狀態
- [ ] 單人模式使用同一套邏輯，不需要任何傳輸，也不經過網路
- [ ] 遊戲核心本身不依賴傳輸層，核心的現有測試維持通過
- [ ] 不依賴真實的 PeerJS 就能完整測試這一層
