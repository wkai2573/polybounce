# Polybounce 規格 0004：擋板內外移動、怪物增量、敵方統一紅色與右側效果面板

**Status：** ready-for-agent

## 問題陳述

玩過規格 0003 之後，有四個問題浮現：

1. BOSS 本體與子彈是橘色，和貫通期間所有彈珠變成的橘色幾乎一樣，混戰時分不清哪個是會扣血的東西。怪物子彈是紅色、BOSS 子彈是橘色，敵方的危險訊號也不一致。
2. 有怪物的關卡太空：每關只有一隻怪物，而且每五秒才向一位玩家射一發，場面稀疏，玩家沒有被壓迫感。
3. 擋板只能沿自己那一邊滑動，深度固定貼邊。玩家要躲子彈只能左右閃，缺少前後走位的空間。
4. 效果倒數分散在兩處：整場效果的標籤在畫面上方中央，個人效果是擋板旁的細條。它們都畫在遊戲場地上，會擋住視線，也沒有剩餘秒數，個人效果還要去找自己擋板才看得到。

## 解決方案

- 怪物與 BOSS 的子彈統一為同一種紅色，以大小區分來源。BOSS 本體改成深紅。橘色只留給貫通。
- 有怪物的一般關卡，怪物數量隨關卡增加，最多四隻，且發射間隔隨關卡縮短，場上子彈自然變多。BOSS 關維持只有 BOSS。
- 每位玩家的擋板除了沿自己那一邊滑動，還能垂直於那一邊往場地內側移動最多一百像素，四個方位對稱。擋板往內移動時，核心、彈珠反彈、道具拾取與發射起點都跟著走。
- 效果倒數集中到場地右側的獨立面板，包含整場效果與每位玩家的個人效果，並顯示剩餘秒數。場地上原本的標籤與擋板旁細條拿掉。

## 實作決策

- **敵方顏色**：
  - 怪物子彈與 BOSS 子彈共用同一個紅色，原本分開的兩個顏色常數合併為一個；半徑不變，一般怪物 8、BOSS 6。
  - BOSS 本體改為深紅，和子彈同屬紅色系，一般怪物維持紫色。
  - 貫通彈珠的橘色與光暈不變，其他道具與磚塊的顏色不動。縮短與縮小兩個 nerf 道具的紅色也不動，靠虛線外框與緩慢飄動和子彈區分。
- **怪物數量**：
  - 一般有怪關卡的怪物數量為：第三關起兩隻，之後每三關多一隻，上限四隻，與玩家人數無關。
  - BOSS 關維持只有 BOSS，血量與彈幕不變。
  - 單隻怪物的血量公式不變。血量降到門檻時的必掉道具規則不變，每隻怪物各自觸發。
  - 生成時多隻怪物的圓心距離至少為兩個半徑，也就是不互相重疊。之後遊走不處理重疊。
  - 過關條件不變。
- **怪物發射**：
  - 每隻一般怪物有自己的發射倒數，歸零時向隨機一位活著的玩家射一發，目標是該玩家核心的實際位置。
  - 發射間隔隨關卡縮短：第三關起為三秒，之後每過五關縮短半秒，最短一點五秒。
  - 每隻怪物的初始倒數在一個間隔內均勻錯開，避免開局齊射。
  - 場上子彈總數上限維持一百，BOSS 彈幕不變。BOSS 的彈幕瞄準目標同樣改為玩家核心的實際位置。
- **擋板深度**：
  - 玩家狀態新增擋板深度，數值為擋板表面離自己那一邊的距離，範圍零到一百。深度最大值寫成常數。
  - 輸入不新增欄位。深度由指標離自己那一邊的距離決定，夾在零到最大值。
  - 瞄準模式下沿邊位置與深度都不更新。死亡玩家不再接收輸入，深度停在死亡時的值，復活後同樣先留在原位，下一個輸入再接手。
  - 核心的位置、無敵閃爍、生命圓點、復活進度的繪製位置都跟著深度走。
  - 擋板表面（彈珠反彈的那條線）、道具拾取範圍與發射起點，都以擋板目前的深度計算。
  - 彈珠漏接判定、子彈越過有玩家那一邊的消失判定、道具飄到邊緣消失的判定，仍然以原本的邊緣為準，不隨擋板移動。
  - 擋板往內移動追上正在往邊緣飛的彈珠時要能反彈；擋板往外移動時，已在板後的彈珠不會被困住，繼續飛出邊緣算漏接。
  - 死亡玩家的方位仍然是邊緣處的牆，屍體畫在死亡時的深度。復活進度仍累計在彈珠撞到該方位屍體沿邊範圍的牆時。
- **前端輸入**：遊戲開始與接關時，把本機指標放到自己那一邊的邊緣，而不是場地中心。其餘指標處理不變。
- **連線**：玩家狀態多一個深度數值，沿用現有的數字壓縮，不新增訊息類型。怪物狀態多一個發射倒數。
- **效果面板**：
  - 版面：場地旁邊新增一欄 DOM 面板，寬度固定約兩百像素。寬螢幕時在場地右側，窄螢幕或直向時移到場地下方。場地的縮放要改為考慮面板所佔的空間。
  - 內容由一個純函式從遊戲狀態與本機玩家的方位推導：全隊區依序為貫通、彈珠大小；各玩家區依玩家座位順序列出加寬或縮短。每一列包含標籤、顏色、剩餘比例、剩餘秒數、玩家方位、是否為自己、是否為死亡。
  - 沒有任何效果的區塊整區不輸出，連標題也不顯示。
  - 死亡玩家的個人效果仍列出，灰色顯示，剩餘時間不倒數。
  - 面板每個畫面更新一次，只讀取狀態，不影響遊戲邏輯與同步。
  - 場地上方中央的整場效果標籤與擋板旁的個人效果細條全部移除。
- **詞彙表**：新增「深度」「效果面板」；更新「擋板」「子彈」「怪物」「BOSS」。其中子彈的「顏色不同」改為「大小不同」，並註明所有敵方子彈同色。
- **文件**：README 的操作說明補上滑鼠另一軸控制擋板內外移動，以及右側面板。

## 測試決策

- **好測試**：只透過公開接縫驗證外部可見的行為；預期值來自獨立推演，不是重新套公式；每個測試一次一個行為。
- **接縫**（沿用現有，只新增一個很小的）：
  - 遊戲核心：建立遊戲、推進一步、讀取狀態快照。深度規則、怪物數量與發射間隔都從這裡測。關卡生成沿用現有的關卡測試。
  - 房主與玩家端會話，用記憶體內的假連線：玩家端收到的深度與怪物發射倒數與房主一致。
  - 新增的小接縫：把遊戲狀態與本機方位推導成面板各列的純函式，用一般的單元測試方式測。
  - 音效事件的差異偵測：這次不動。
- **會被測試的行為**：
  - 深度：指標離自己那一邊越遠，深度越大，夾在零到最大值；四個方位對稱；瞄準模式下沿邊位置與深度都不變；死亡後不更新，復活後留在原位。
  - 判定隨深度：核心受擊位置、彈珠在擋板目前表面反彈、道具在目前位置被接到、發射起點。
  - 判定不隨深度：彈珠穿過擋板後飛出邊緣算漏接、子彈越過邊緣才消失、道具飄到邊緣才消失。
  - 追球與退讓：擋板往內移動時能反彈正往邊緣飛的彈珠；往外移動時板後的彈珠不被困住。
  - 怪物數量：第三關起兩隻，之後每三關多一隻，上限四隻；與玩家人數無關；BOSS 關只有 BOSS；多隻怪物生成時互不重疊；過關需要全部清除。
  - 怪物發射：發射間隔隨關卡縮短且有下限；各自計時，初始倒數錯開；目標是活著的玩家核心的實際位置；子彈總數達上限時不再發射。
  - 敵方子彈顏色統一：這是繪製常數，靠手動驗證，不自動測。
  - 面板推導：全隊區與各玩家區的內容與順序、只列出生效中的效果、沒效果時整區不輸出、自己那一列標記、死亡玩家標記且剩餘時間不變、剩餘秒數取一位小數。
  - 連線：玩家端收到的深度與怪物發射倒數與房主一致。
- **不測試**：面板的實際 DOM 外觀與響應式版面、子彈與 BOSS 的顏色、擋板在不同深度的繪製、開局指標放在邊緣的前端處理，只靠手動驗證。
- **先例**：現有的生命與核心測試、彈珠大小測試、關卡生成測試、彈幕測試、會話測試與狀態壓縮測試。
- **需要改寫的既有測試**：
  - 各測試共用的輸入輔助函式，原本把指標的另一軸固定在零；改為把指標放在各玩家自己那一邊的邊緣，否則深度會被夾到最大值而讓所有位置計算偏移。
  - 假設有怪關卡只有一隻怪物的測試改為新的數量規則。
  - 假設全場共用一個怪物發射倒數的測試改為每隻怪物各自計時。

## 不在範圍內

- BOSS 關加入小怪。
- 怪物之間的碰撞。
- 依玩家人數調整怪物數量或血量。
- 調整場上子彈上限與 BOSS 彈幕密度。
- 效果面板以外的 HUD 重做，也不搬動關卡、分數與彈珠池資訊。
- 其他道具與磚塊的顏色調整。
- 用鍵盤或滾輪控制深度。
- 深度的自動回彈或慣性。
- 為手機觸控另外設計控制方式。

## 補充說明

- **暫定值**：深度上限一百、怪物數量曲線、發射間隔曲線、面板寬度，都應寫成常數，實作後依手感調整。
- **假設，提交前請確認**：死亡玩家的牆仍在原本的邊緣，而屍體畫在死亡時的深度。屍體因此可能漂在離牆最多一百像素的地方，彈珠會從屍體圖示旁穿過、撞到後方的邊緣才反彈與累計復活。這是依「屍體停在原位」與「判定線不隨擋板移動」兩個決定推導出來的結果，視覺上可能怪，若實測不順再改成死亡時把屍體貼回邊緣。
- **怪物錯開發射**：初始發射倒數在一個間隔內均勻錯開，是為了避免齊射而加的細節，盤問時沒有明確討論。
- **對既有規則的改動**：規格 0003 中「畫面上方顯示目前的整場效果與剩餘時間」，以及擋板旁的個人效果細條，都由本規格的右側面板取代。「BOSS 的子彈用原本的顏色區分來源」改為只用大小區分。
- **詞彙**：本規格使用的術語以專案的詞彙表為準；「球」一律指彈珠，不是子彈。
